# Cross-validation against SciPy / scikit-learn / PyTorch / NetworkX

Each `crates/oxideon-core/tests/crossval_emit*.rs` file is an `#[ignore]`d test that prints `name value` lines computed by
oxideon on fixed, deterministic inputs. The matching `check_batch*.py` script recomputes the same quantities with an
independent library and compares them (relative error, usually `1e-6`).

```
cargo test -p oxideon-core --test crossval_emit3 -- --nocapture --ignored > rust_values3.txt
py -3.11 tools/crossval/check_batch3.py rust_values3.txt
```

Deliberate differences (documented in the code, excluded from the checks): `std` adds `1e-12` under the square root so the gradient is finite at zero variance (a constant gives `1e-6`, PyTorch 0); `softmax` / `log_softmax` of a row containing `+inf` return the limiting distribution (PyTorch NaN).

Not comparable value-for-value: `Muon` (PyTorch orthogonalizes in bfloat16 and uses an EMA momentum buffer; ours runs in
full precision with the Moonlight-style update scale).

Real defects these checks found and that were fixed: Butterworth high-pass pole scaling, FIR high-pass design (now matches
`scipy.signal.firwin`), an infinite loop in `i1`/`i1e` at `x = 0`, `multilabel_margin_loss` counting target-vs-target pairs,
CTC `mean` reduction not dividing by target length, `scatter_reduce(sum|mean, include_self=false)` zeroing slots nothing was
scattered into, and `ComplementNb` lacking scikit-learn's default (un-normalised) weights, `clamp` zeroing the gradient at its bounds (PyTorch passes it; only `hardtanh`/`relu6`/`hardsigmoid` zero it),
`max_axis`/`min_axis` splitting the gradient among ties (PyTorch gives it to the first; `amax`/`amin` split evenly, now
over all reduced axes at once), `diag_embed` rejecting batched input, `max` / `min` / `amax` / `argmax` (and so max pooling and the inf-norm) silently ignoring NaN, `log_softmax` losing the `ln(sum)` term for very large logits, integer `floor_divide` / `remainder` truncating toward zero and `fmod` failing on integer tensors, float `floor_divide` being off by one near exact multiples, `relu(NaN)` returning 0, `hypot(inf, NaN)` returning NaN, `Tensor::round` rounding halves away from zero on the CPU backend (PyTorch, NumPy and the GPU path round half to even), top-p sampling keeping one token too many when the cumulative mass lands exactly on `top_p`, `BatchNorm3d` using the biased variance for `running_var`, `Binomial::entropy` / `Poisson::entropy` not being differentiable, `svd()` returning `U` / `Vt` with no gradient (only `S` was differentiable), `multilabel_margin_loss` and `ctc_loss` returning tensors with no autograd graph (they could not be trained with),
`triplet_margin_loss` omitting PyTorch's `eps = 1e-6`, `celu` having gradient 0 instead of 1 at exactly 0, `max_unpool2d` summing (instead of overwriting) elements that
are the maximum of several overlapping pooling windows, `jaro_winkler` boosting shared prefixes below
Winkler's 0.7 similarity threshold, and Bayesian-optimization expected improvement using a 1e-7-accurate erf (relative
errors ~1e-5 in ordinary cases, negative EI in the tails).

Caveats: the randomized structures (sketches, optimizers, TPE, BO, particle filter) are checked against their
theoretical guarantees or an exact solution with generous tolerances, not value-for-value, because no reference library
shares their random streams. Soundex, the Kalman reference (same textbook recursion) and sep-CMA-ES on rotated problems
(Rosenbrock converges only to ~1e-3) are the weakest checks.
